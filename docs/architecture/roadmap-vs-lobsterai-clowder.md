# myteamOUO 对比 LobsterAI / Clowder AI 的迭代路线

更新时间：2026-06-20

> 说明：本文将“LOBAI”按 [LobsterAI](https://github.com/netease-youdao/LobsterAI) 理解。结论基于 2026-06-20 两个公开仓库的 README 与 myteamOUO 当前实现；竞品未做完整安装实测的能力，不写成实测结论。

## 结论先行

myteamOUO 不应该同时追赶两个竞品的全部功能。

- LobsterAI 的优势是“桌面级全场景办公 Agent”：安装分发、OpenClaw 运行时、Skills、MCP、定时任务、长期记忆和 IM 触达。
- Clowder AI 的优势是“有身份和纪律的多 Agent 团队”：跨模型审查、共享记忆、A2A、Mission Hub、SOP、成本与能力治理。
- myteamOUO 更适合占据“轻量、本地、透明、可验证的多 CLI 协作控制面”：复用用户现有 CLI，不要求完整桌面运行时，让每次分工、证据、审批、返工和恢复都能看见。

因此下一阶段的目标不应是“功能数量追平”，而应是证明：在 2–3 个复杂任务中，myteamOUO 能比手工打开多个终端更快、更少返工、更值得信任。

## 当前相对位置

| 维度 | myteamOUO | LobsterAI | Clowder AI |
|---|---|---|---|
| 核心定位 | 本地 CLI 的轻量协作控制面 | 桌面级全场景办公 Agent | 多 Agent 团队与协作治理平台 |
| 运行形态 | 单 Node 服务 + Web UI | Electron + OpenClaw | 多包平台 + Web/桌面分发 |
| Agent 接入 | Codex / Claude Code / Kimi CLI | OpenClaw 引擎、模型与 MCP 生态 | Claude / Codex / Gemini / opencode 等统一消息层 |
| 协作 | 结构化 Plan、派生任务、Reviewer Gate | Cowork 会话、子 Agent、Skills | A2A、跨模型审查、持久身份、SOP |
| 上下文 | Capsule + Top-K + Git 工作区快照 | 持久记忆、文件与本地环境 | 共享记忆、证据、决策日志 |
| 安全 | 服务端审批、指纹、脱敏审计 | 桌面权限请求与日志 | Iron Laws、平台治理与审计 |
| 自动化 | Cron、审批暂停、产物 | 定时任务、浏览器、邮件、IM 等 | Mission Hub、流程治理、外部渠道 |
| 分发成熟度 | 源码启动 | 跨平台桌面安装包 | 桌面安装器 / 源码安装 |
| 当前主要短板 | 用户验证、安装、场景、真实成本与质量指标 | 对 myteamOUO 不是主要比较劣势 | 对 myteamOUO 不是主要比较劣势 |

## myteamOUO 已有的可守优势

### 1. 低迁移成本

用户继续使用已经登录和配置好的 CLI；系统只增加协作层，不要求先接受一套完整新运行时。

### 2. 协作过程透明

结构化任务、验收标准、工具时间线、Reviewer Gate、审批和恢复都显式呈现，适合需要理解和控制过程的开发者。

### 3. 产品与架构边界清楚

项目明确承认权限控制只覆盖自身入口，不用“本地”或“AI 自动化”掩盖安全边界；这可以转化为可信赖的产品表达。

### 4. 轻量实验速度

单服务、原生 Web UI、SQLite 的组合便于快速改动和验证，不必为桌面打包、网关和生态兼容承担同等成本。

## 最值得补齐的差距

### P0：先证明产品价值（2–4 周）

截至 2026-06-21，已完成第一批体验基础：Agent/工作区健康提示、四个高频场景模板、用户可理解的任务生命周期，以及带自动审查证据的人工 Reviewer 评分卡。下一步重点转向基准任务、首次成功数据和任务回放指标。

#### 1. 建立 3 个基准任务与对照实验

选择高频且能体现协作价值的场景：

- 仓库诊断与修复：分析 → 实现 → 测试 → 审查；
- 竞品研究与产品方案：检索 → 归纳 → 质疑 → 输出 PRD；
- 数据到报告：采集 → 计算 → 写作 → 一致性校验。

对比“手工多终端”和“myteamOUO”两种方式，记录：

- Time to First Value；
- 总完成时长；
- 人工复制/解释上下文次数；
- 人工介入与返工次数；
- 验收通过率、恢复成功率；
- Token/费用与主观信任评分。

**价值：** 这是当前最缺的证据，也会直接决定后续功能优先级。

#### 2. 重做首次使用路径

- 自动检测 Node、CLI、登录状态和可写目录；
- 提供“一键健康检查”和可执行修复建议；
- 内置一个 5 分钟样例任务，让用户第一次打开就完成协作闭环；
- 展示最小配置，不先暴露全部 Hub 能力。

**竞品启发：** LobsterAI 与 Clowder AI 都在加强安装和引导；myteamOUO 的轻量优势只有在“真的更快跑起来”时才成立。

#### 3. 把任务回放升级为产品指标面板

不要只统计调用次数。按一次任务展示各阶段耗时、Agent、上下文来源、工具调用、审批、返工、失败和成本，支持与历史任务比较。

**价值：** 形成 myteamOUO 的差异化资产，也为智能路由提供训练数据。

### P1：做深“可信协作”（1–2 个月）

#### 4. Evidence-first 本地知识层

在当前 Top-K 关键词检索上增加：

- 文档切片与 embedding 检索；
- 每条结论显示来源文件、时间与片段；
- 记忆写入前审核、过期与遗忘机制；
- 冲突证据提示，不静默覆盖旧决策。

**差异化：** 不只“记得更多”，而是让用户知道 Agent 为什么这样判断。

#### 5. Reviewer Scorecard

把通用 Reviewer Gate 升级为按任务类型配置的评分卡：正确性、完整性、安全性、可维护性、证据充分度。记录 Reviewer 建议被接受、驳回和最终验证的结果。

**竞品启发：** Clowder AI 强在跨模型 review 和 SOP；myteamOUO 可以用更轻的方式把验收做得更可量化。

#### 6. 权限 Adapter 与最小能力授权

- 给不同 Agent/Skill 配置文件、命令、网络和目录能力；
- 将外部 CLI 可暴露的原生 permission event 接入统一审批；
- 提供 dry-run、只读模式和项目级策略模板；
- 审计页支持按任务回放授权链路。

**竞品启发：** LobsterAI 的桌面权限是成熟方向；myteamOUO 应继续强调边界明确，而不是用一个总开关假装安全。

#### 7. 标准化 Adapter SDK

把 CLI 接入抽象为清晰契约：能力探测、参数模板、流式事件、工具调用、取消、恢复、usage 和 permission。提供最小示例与契约测试，降低接入 Gemini CLI、opencode 或企业内部 Agent 的成本。

### P2：扩展生态，但保持克制（2–3 个月）

#### 8. MCP 与 Skill 治理

- 支持 MCP Server，但默认关闭外部网络与写权限；
- Skill 增加版本、依赖、来源、签名/哈希和兼容性；
- 安装前静态检查危险命令与过宽权限；
- 项目锁定 Skill 版本，保证任务可复现。

#### 9. 场景模板，而不是功能市场

先发布 3–5 个完整“任务包”：角色、Skills、Reviewer 评分卡、示例输入、验收规则和指标，而不只是单个 Skill 列表。

**原因：** 用户购买的是任务结果，不是能力零件。

#### 10. 独立安装与后台运行

先做可执行安装器、后台服务、托盘入口和安全升级，不必立刻重写成 Electron。只有当系统级文件、通知和多窗口成为高频需求时，再评估桌面壳。

#### 11. 通知和远程触达后置

先支持任务完成/审批通知，再考虑完整 IM 对话。远程控制会扩大凭证、暴露面和运维责任，必须复用同一套审批与审计。

## 暂时不要做

- 不要追 20+ Skills 数量；先证明 3 个任务包的完成率。
- 不要先做 AI 角色陪伴、语音和内容 Feed；这属于 Clowder AI 的定位，不是当前核心假设。
- 不要先复制全场景办公生成；LobsterAI 的运行时和生态优势很难靠功能清单追平。
- 不要把 LangGraph、Electron 或向量库本身当作版本卖点；只有用户指标需要时才引入。
- 不要在缺少 usage 数据时宣传“降低成本”；先完成真实记录与对照实验。

## 建议的北极星指标

**每周通过验收的复杂任务数（Weekly Accepted Complex Tasks）**

配套指标：

- 首次成功任务耗时；
- 任务一次验收通过率；
- 每任务人工上下文搬运次数；
- 中断恢复成功率；
- Reviewer 发现的有效问题数；
- 每个通过任务的时间与模型成本；
- 7 日仍在使用的激活用户比例。

这个指标比“调用次数”“Agent 数量”“Skill 数量”更接近项目真实价值。

## 推荐的一句话定位

> myteamOUO 是面向 AI 重度用户的本地多 Agent 协作控制面：复用已有 CLI，让复杂任务的分工、证据、审查、权限和恢复都可见、可控、可复盘。
