## 二、关键架构决策

### 1. Reviewer 选择：路由层预选 cross-family（对齐 clowder-ai）
不再让 codex/codex-dev 当 reviewer（codex 是总控角色 + 无 CLI 禁 tool 解 + 忽略 prompt）。优先 claude 变体（`--disallowedTools` 禁工具但默认模式能真评审）。`server.mjs runAutoReview` 选择顺序：claude 变体 → 非 codex 变体（kimi）→ 兜底。

### 2. Reviewer 工具约束：per-call extraArgs（不动全局 argsTemplate）
`invokeAgentOnce` 加 `extraArgs` 选项，review 调用时按 reviewer 注入：
- claude → `--disallowedTools Bash Read Write Edit Glob Grep WebSearch WebFetch Task NotebookEdit MultiEdit`（禁工具但默认模式）
- codex → `[]`（无禁 tool flag，靠强 prompt + read-only + 证据）
执行器走 `streamAgent`，完全不碰 extraArgs → claude 当执行器时全工具照常。

### 3. 评审裁决：关键词 fallback（不依赖严格 JSON）
参考 clowder-ai，`parseReviewOutput` 在 JSON/zod/fallback 全失败时用 `detectVerdictByKeyword`（rework 信号优先保守）从原文提取 verdict，不再返回 null → `review_protocol_failed`。覆盖 reviewer 输出自由文本的场景。

### 4. 低分护栏：转人工 gate（不自动打回）
`verdict=pass && score<60` → `gate_status='waiting'`、`phase='gate'`，加 finding"评分 X/100 低于 60，已转人工验收"。用户在 Hub gate tab 决定 pass/rework，不自动返工（用户要求：通过就不重做）。

### 5. 统一权限总开关：autoApproveTools（默认开）
`settings.json` 加 `autoApproveTools`，streamAgent/invokeAgent 启动时按 CLI 注入 bypass flag。设置抽屉一处控所有 agent，动态生效无需重启。codex 因 sandbox 机制无法细粒度（WebSearch 要联网只能全访问档），这是 codex CLI 限制。
